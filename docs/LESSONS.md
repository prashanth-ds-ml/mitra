# Lessons

Rules learned the hard way, so the same mistake is not made twice. Read the relevant ones before starting work.
Each lesson links the error that taught it. Seeded from Research Desk (project 04, `R-E-nnn` = its ERROR_LOG), the
local-codex review and this project's planning. Add a lesson whenever an error could happen again somewhere else.

| ID | Area | Rule | Learned from |
|---|---|---|---|
| L-001 | Ollama | Set the context length explicitly (`OLLAMA_CONTEXT_LENGTH`); the 4K default drops the start of long prompts with no error. Log prompt tokens on every call | Research for 05 (agents breaking on local models) |
| L-002 | Ollama | A dead or unreachable model must fail loudly. Empty output is an error, never a pass | R-E-005 |
| L-003 | Timeouts | Every model call and subprocess gets a timeout; stream with a runaway guard | Project 04 1.5 h hang |
| L-004 | State | No per-run state in module globals; pass a run object | R-E-004; local-codex `_config`, `_guard`, `_active_change_set` |
| L-005 | Small models | Cap thinking and test with thinking on and off; thinking at temperature 0 may never finish | R-E-014, R-E-021 |
| L-006 | Small models | Prefer scoring or ranking to yes/no judgments; small models reject almost everything on yes/no | R-E-015 |
| L-007 | Ollama | Batch requests; one huge request (hundreds of embeddings) can crash the runner | R-E-018 |
| L-008 | Machine | Ollama maps ~8 GB of RAM on Windows; check free RAM >= 11-12 GB, one model loaded at a time. Look at the whole picture before stopping one process: stopping a 9.6 GB backend still left 2.7 GB free because browsers held ~9 GB (group memory by process name) | R-E-022; 05 M0, 2026-10-25 |
| L-009 | Env | After installing into the shared venv run `uv pip check`; mismatched package pairs break startup | R-E-016 |
| L-010 | Release | Test a fresh clone before every release; check ignore rules with `git check-ignore -v` | Research Desk v0.3 (a hidden ignore rule kept a whole page out of git) |
| L-011 | Paths | Create a directory before `cd`/clone into it and verify where files landed; a failed `cd` put a clone in the wrong project | 05 planning session, 2026-10-24 |
| L-012 | Tests | Test every member of a set, not one example: `edit_file` was missing from `mutating_tools` and tests only used `create_file` | local-codex `app/langgraph_workflows.py:55` |
| L-013 | Loops | Every agent loop has a step limit and a repeat-call guard | local-codex `while True` loops (`filesystem.py:958` and others) |
| L-014 | Safety | Checking only the program name allows anything (`python -c ...`); path checks must fail closed when no workspace is set | local-codex `shell.py:407`, `shell.py:207` |
| L-015 | LangGraph | Cancelling a run does not stop a running sync node; use a cooperative stop flag | Project 04 close-out |
| L-016 | Planning | An idea is not a decision. New ideas go to "Ideas to test"; never record one as agreed without the user saying so | 05 planning, D-008 |
| L-017 | Tooling | Long nested heredocs fail in the Bash tool; use Write/Edit. Never print `.env` unfiltered | Project 04 |
| L-018 | Lint | Gate CI on syntax errors and undefined names (`ruff` E9/F63/F7/F82) from day 1; it finds crashes no test covers | E-004 |
| L-019 | Portability | Build paths with `pathlib`, store them relative with `/`, never assume PowerShell; run CI on Linux and Windows from the first commit | E-005 |
| L-020 | Benchmarks | The agent's environment must match the grader's: same `python` on PATH, same packages; check it with a test before any real run | E-006 |
| L-021 | Git | `git diff` ignores untracked files; `git add -A` then `git diff --cached <start>` to capture everything an agent changed | E-007 |
| L-022 | Tests | Any test that depends on prompt length asserts the prompt tokens Ollama reports; measure the size, never estimate it in a comment. A cut prompt is a void case, not a model failure | E-008 |
| L-039 | Tools | Parse commands the way a shell does: separators and pipes inside quotes are part of an argument. A program stopped at the time limit without an error (game, window, server) is running, not failing: say so to the model, or it will "fix" working code. (E-040, E-041) |
| L-038 | Self-improvement | Judge the settings in use, not all history: analyse only the records made with the current harness version, or a fixed problem stays on top forever. Anything the loop may add to the prompt counts against the token budget at its maximum, checked in CI. (E-036, E-038) |
| L-037 | Evals | Before trusting an A/B, grade the reference solution through the same path from the same Python (the installed tool's, not the repo venv). A grader that breaks must stop the comparison, never count as the model failing. (E-035) |
| L-036 | Loops | A guard must judge a call by its real result, not by how the output text starts, and an exemption ("commands may repeat") needs a condition ("after a change"). Show the reason for a failure on screen: a stuck loop that says only "failed" looks like a mystery | E-033 |
| L-035 | Install | Test the installed command, not only the source checkout: it runs a different Python. Never reinstall a tool while it is running (Windows locks the exe after the packages are already gone); install into the existing env instead | E-028, E-029 |
| L-034 | Git | Before reusing a helper for a user command, read what it runs: an agent's `git_commit` stages everything (`git add -A`). Test user-facing git commands against a real temp repo and assert the exact commands run | E-027 |
| L-033 | Context | How full the context is = the prompt tokens of the latest call. Summing tokens across calls measures work done, not context, and grows much faster | E-025 |
| L-032 | Tools | Test every tool against the real service from this machine before relying on it, and prefer open APIs over scraped pages. When a loop is cut short, still ask the model for an answer from what it has: the user asked a question, not for a stop message | E-024 |
| L-031 | Loops | A step limit is not enough: small models repeat a failing call until the limit. Refuse identical repeats, stop after a few failures of the same tool, and tell the user the real cause (offline, blocked) | E-023 |
| L-030 | Interface | Every turn ends with something visible: an answer, a tool result or an error. Check the empty case at every model call, not only the first. When commands are removed, a test must scan the code for mentions of them | E-020 |
| L-029 | Routing | Nothing that changes files may start from a question or from a message that says not to change anything. Keyword routing must match whole words and must check for questions and "no coding" first; the user's real messages from the trace are the test cases | E-019 |
| L-028 | Tools | Every tool call returns a result to the model, even when the call is wrong: catch argument errors and crashes at the one place tools are invoked and report them as a tool error. Small models get argument types wrong often; a crash costs the whole turn, an error message costs one retry | E-018 |
| L-027 | Interface | When replacing an interface, list every output path first (grep `Panel(`, `console.print`, dialogs) and remove the old ones in the same change; then check a whole session start to finish against the mock, not only the part that was rebuilt | E-017 |
| L-026 | Models | Check what the client library does with a thinking model's reasoning before building UI on it: langchain-ollama drops it unless `reasoning=True`. Test every streaming change live against the real model, not only fake chunks | E-016 |
| L-025 | Editing | When a scripted edit targets a line that appears more than once, anchor it inside the target function (find the function first, then the line) and assert the count; and treat the user's own typed input differently from model requests: the user is the author | E-014, E-015 |
| L-024 | Protocols | Never hand-write a protocol client that has an official SDK; and test any client against a server you did not write, or it only proves it talks to itself | E-012 |
| L-023 | Benchmarks | Fakes only prove what they imitate. Before a benchmark, run every agent config once for real (one call) and read its log: real agents call lookup endpoints, send title calls first, use other APIs (Responses) and need their own folders | E-010, E-011 |
| L-046 | Model | Before fixing behaviour in the harness, test the model alone with a plain prompt: mimo with no tools and no Mitra still turned "either X or Y" into a product design and "think deep" into 892 words, while qwen3.5 answered in 50 words with a good question. Two rounds of prompt fixes had moved mimo only from 9 to 11 of 19. Pick the model by data (a screen + the score), not by "for now" (D-057) | D-072 |
| L-047 | Process | Compare architectures through the chat's own entry on the same score, same model, same context, and read the failed answers before concluding: the totals hid that the router wrote reports, one loop over-acted (built an app unasked) and qwen's misses were mostly citations and empty endings, all fixed in the harness. Give the model the decision, but offer tools only after it chooses to act (phased) | D-071, E-100 |
| L-048 | Design | When the model offers to do something and the user says yes, the harness starts it; a yes is never sent back to the model to decide again. A small model that has asked a question once copies it from the history: check a talk answer against the last answer and never accept a repeat | E-125 |
| L-045 | Process | Check a change against the user's real data, not only tests: `mitra report` and insights on the real store found empty-answer false positives and 10 polluting dev folders that 837 green tests missed. Dev and live-check scripts never write into the user's ~/.mitra (temp workspaces are not mirrored); a test that leaves a thread running joins it before it ends. Sweep the sorter with realistic follow-ups ("still not working", "why?"), not just first messages | E-093, E-094, E-095 |
| L-044 | Backends | `config.load()` points the whole process at an active Kaggle remote (URL, 256K, OLLAMA_HOST). Anything that must run on this machine (a score, a benchmark, the laptop fallback) takes its settings from `cfg['_local']`, and says which machine it used. Anything unattended has a wall-clock limit per case: a stalled tunnel stream never ends on its own. A request that goes through the tunnel must stream (Cloudflare closes a reply that sends nothing for 120 s) | E-079, E-081, E-082 |
| L-043 | Design | A limit or promise is enforced where the action runs, not only in what the model is shown: role tool sets filtered the tool list but `_run` ran any named tool; `/model use` saved a setting a higher-priority one overrode. When two code paths compute the same thing (context size), keep one function both call | E-054, E-055, E-061 |
| L-042 | Process | A report states what actually happened, checked in code, never what was meant to happen: the night report said "rolled back" after a kill that skips the rollback. Stopping a run means stopping its whole process tree; a sub-workspace shares the parent's journal and records | E-053, E-064 |
| L-041 | Process | A running Mitra keeps the code it started with, but `/run` starts a child process that loads the code on disk: editing Mitra while it runs gives two versions at once (the chat's old plan check said ✓, the night's new one refused). Change code only with Mitra and nights stopped; restart Mitra after every change; the header shows the commit it runs | E-049, E-050 |
| L-040 | Model | A model or server error the model caused (a broken or cut-off tool call) goes back to the model as a note and a retry, like a failed tool, never a crashed turn; cap the retries. Small models write huge single tool calls: steer long files into parts (E-044) |
